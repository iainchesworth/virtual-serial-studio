**The user-mode Windows driver can now make virtual COM ports on demand, like the kernel-mode one.** A new service, `vsscom_helper`, runs as SYSTEM and makes the ports for ordinary users, so the studio no longer needs an administrator to open a port with the user-mode driver. It keeps the control device's rules: 16 ports for one user and 32 in all, the lowest free slot so a port keeps its COM name, a port that goes when the program that asked for it exits, and a hub end that opens only for the user who asked for the port. The driver reads that owner from the device, and the studio asks the kernel-mode control device first and the helper second. `install-driver.ps1 -Helper` installs the service in a test guest, `install-helper.ps1` installs it elsewhere, and CI builds, signs and uploads it as `vsscom-helper-<platform>`.
