**The GUI has a UI-driven test suite.** `vss_gui_ui_tests` drives the real main window with simulated mouse clicks, key presses, drags, context-menu events and drops, offscreen, and answers the dialogs it opens the same way. Its journeys cover every job of Simple mode, the same outcomes built by hand on the Advanced canvas (every port and bundle type, wiring, moving, menus, the Send and Monitor docks, undo, workspace files), the awkward cases (cancelled dialogs, empty and duplicate names, many items, every pair of port types, rapid clicking, resizing, 200 percent text, both themes) and a group on the real engine. Each journey also fails when the GUI thread computes longer than the journey's budget (`ui-tests/perf_budgets.json`), a freeze ends with the step it hung in, and a failed journey saves a PNG of the window. They run as the `ui_simple`, `ui_advanced`, `ui_edge` and `ui_engine` CTest tests (label `ui`, run one at a time, `ctest --preset <platform>-gui-ui`) and in the GUI leg of CI. Every GUI test program now keeps its `QSettings` in a directory of its own, so two of them no longer clear each other's settings. `docs/testing.md` maps the journeys.
