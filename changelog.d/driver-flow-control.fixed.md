**On Windows, the driver now does what `SetCommState` asks of DTR and RTS.** DTR and RTS control set to enable or disable raise or drop the line, handshake makes the line follow the receive buffer (it drops when 4 KB or so is left free and rises when the buffer has emptied below the limit you chose), and RTS toggle holds RTS high from the first queued byte until the last has had time to leave at the current baud rate. A program that relies on `SetCommState` to raise DTR or RTS, which is common in old code, now shows both high to the peer. The port goes back to no DTR or RTS control, no handshake, each time a program closes it, and `EscapeCommFunction` refuses to set a line that is in handshake mode, as a real port does.
