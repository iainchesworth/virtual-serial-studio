**On Windows, Studio now knows when a program has a port from its driver open.** `vss::peer_open` answers for a port of the Virtual Serial Studio driver, so the Ports list can show *Waiting for program* and *Program connected* as it does for a pseudo terminal on Linux, and the driver's line settings (baud rate, data bits, parity, stop bits) and the program's process id are available to ask (`vss::driver_peer`). Each time a program opens or closes a port, the endpoint's log gets a line with the time and the process, so a hung program can be diagnosed afterwards. Transports can now put a line in their endpoint's log. Every other COM port, such as hardware or com0com, still reads as unknown.
