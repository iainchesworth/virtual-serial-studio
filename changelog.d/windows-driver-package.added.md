**The Windows virtual COM port driver builds in CI.** The `vsscom` driver is in the tree again, with a valid INF, and CI builds and packages it for x64 and ARM64 on every change that touches it: `drivers/windows/build.ps1` restores the Windows SDK and the WDK from NuGet, builds, runs `InfVerif` and `Inf2Cat`, and CI uploads `vsscom.sys`, `vsscom.inf` and the catalog as an artifact. The driver now registers its COM name the way Windows serial drivers must, with the `GUID_DEVINTERFACE_COMPORT` interface, the `\DosDevices` link and the `SERIALCOMM` entry, and a second `CreateFile` on an open port fails. The package is not signed and has not been loaded in a guest yet, so `vss::driver_available()` still reports no driver.
