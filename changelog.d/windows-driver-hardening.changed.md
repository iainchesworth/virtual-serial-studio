**The Windows virtual COM port driver is tighter and has been run under Driver Verifier.** A write that waits for the hub now obeys the write timeouts of `SetCommTimeouts` and completes with the bytes it had taken. The hub end of a port made on demand opens only for the user who made it, the hub end of a port made by hand opens only for administrators, and one user holds at most 16 of the 32 ports. The whole guest suite passes with Driver Verifier on, and a new guest test, `test-client.ps1`, runs the studio's own client against the installed driver: it makes a port, carries bytes both ways, drives the control lines and removes the port. `vss::create_driver_port()` reports `port_exhausted` when a user is at the limit.
