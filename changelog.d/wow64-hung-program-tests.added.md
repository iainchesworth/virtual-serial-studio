**The Windows driver is tested with a 32-bit program and with a program that hangs.** A small C client, built as Win32, x64 and ARM64 and built in CI, probes `COM1` to `COM16`, makes the calls an old program makes (`SetCommState` with the DTR and RTS modes, `SetCommTimeouts`, `GetCommProperties`, `GetCommConfig`, `EscapeCommFunction`, overlapped `WaitCommEvent`, `ReadFile` and `WriteFile`, `PurgeComm`) and holds a port with requests pending. `test-wow64.ps1` runs it in the Windows guests, where the 32-bit build runs under WOW64 against the 64-bit driver, and checks that a killed or suspended program frees its port, what a second open gets, what happens to a port that is removed under a held handle, and what a helper service restart does. `tools/vm/guest-cell.ps1 -DriverBundle` runs the whole thing from the clean snapshot, and `tools/vm/make-driver-bundle.ps1` builds its bundle.
