**On Windows, the studio can take a port back from a program that has hung on it.** The driver gains a revoke request for the end that Studio holds: the program's waiting reads, writes and `WaitCommEvent` end, its handle fails from then on, and another program can open the port at once, without a restart and without a different COM number. The driver also tells Studio which process has a port open. This changes the driver's interface (version 3), so the driver and Studio have to be updated together. The Studio window does not offer revoke yet.
