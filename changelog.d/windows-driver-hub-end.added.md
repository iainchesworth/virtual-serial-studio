**Each port of the Windows virtual COM port driver has a hub end.** The studio opens a second handle on a port through a device interface, reads what the application wrote and writes what the application reads, with a 64 KB queue each way and a write that waits when the queue is full. The hub sees the baud rate, line settings, DTR, RTS and break that the application sets, without polling, and it sets CTS, DSR, carrier detect and ring. Each end has one handle at a time, and a port with no hub handle loops back as before. `install-driver.ps1` now creates two ports, and `test-driver.ps1` runs six more checks, D8 to D13, in a guest.
