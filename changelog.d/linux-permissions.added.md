**On Linux the Setup check explains why a serial device is refused and gives the exact fix.** A *Serial device access* row reads the owner group and mode of each device and says whether your account is missing the group (with `sudo usermod -aG dialout <you>`, and a button that asks polkit for your password and runs just that command), the group is not yet known to this login, the mode forbids it, or something outside the file permissions refused it. A *Confinement* row appears when Flatpak, Snap, AppArmor or SELinux is in force and shows the override, the profile lines to add or the `audit2allow` commands. A *Firewall* row shows the `ufw` or `firewalld` command that opens a port you listen on, and says "Not checked yet" where the rules cannot be read without root. A "permission denied" error on Linux and macOS no longer talks about Windows administrator rights. `vss_cli permissions check --device=... --listen=...` prints the same facts.
