**The Windows virtual COM port driver makes ports on demand.** A control device, installed once from `vsscomctl.inf`, creates a port when a handle on it asks for one, and removes the port when that handle closes or the process ends, so a studio that crashes leaves nothing behind. A port keeps its slot, and with it its COM name, from one run to the next. Any signed-in user may open the control device, and at most 32 ports exist at once. `vss::create_driver_port()` now asks the control device for a port of its own, waits for Windows to build it, and falls back to the ports that exist when the driver has no control device. It reports `port_exhausted`, `permission_denied` and `timeout` as well. The package now holds two INF files and two catalogs, `install-driver.ps1` installs both, and `test-driver.ps1` runs six more checks, D14 to D19, in a guest.
