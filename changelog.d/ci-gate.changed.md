**CI follows the shared gate.** A policy job (branch name, commit and pull request text, committed-file text, action pinning, changelog fragment, vcpkg baseline, REUSE) and a planner run first, and documentation-only changes skip the builds. Builds skip draft pull requests. The workflow also runs for merge-queue entries, every action is pinned to a commit, and workflow analysis (zizmor) and a dependency review run on every pull request. The `CI Status` and `Scan dependency diff` jobs are the checks a ruleset can require. The separate `Commit text` job is gone because the policy job covers it.
