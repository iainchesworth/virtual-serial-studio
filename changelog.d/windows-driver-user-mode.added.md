**There is now a user-mode driver for the Windows virtual COM port, beside the kernel-mode one.** `vsscom_um` is a UMDF 2 driver for the same port, built from the same sources: the COM name, the application end, the hub end, the serial rules and the write timeouts, with the same hub interface, so the studio finds the ports of either driver. It runs in a driver host process and needs no kernel-mode signature. You choose which to install, and both can be installed together because their hardware IDs differ. The user-mode driver has no control device yet, so its ports are made by hand. The build makes both packages, and the guest scripts take `-Flavour kmdf` or `umdf`.
