**Virtual ports can have a stable name.** A new `stable_link` module in `vss_ports` makes a symbolic link such as `$XDG_RUNTIME_DIR/vss/ttyVSS0` that points at a pseudo terminal's current `/dev/pts/N`, so scripts and configuration files can name a port that stays the same between runs. The directory is `$VSS_VPORT_DIR`, then `$XDG_RUNTIME_DIR/vss`, then `/run/vss` and `/tmp/vss` on Linux or `/tmp/vss` on macOS. It is created closed to everyone but its owner and is refused if it is not. A link left behind by a process that died is replaced; a link to a device that is still there, and anything that is not a link, are not. The Windows build reports the module as unsupported, because the driver will own the `COMn` names. Nothing calls it yet; `vss_cli vport` and the studio follow in the next changes.
