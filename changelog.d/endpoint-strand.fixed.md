**Endpoint read and write completions run on the endpoint's strand.** The completion handlers were wrapped with `bind_executor`, but they pass through a `std::function`, which carries no executor, so the binding was lost and a completion ran on whichever hub thread finished the I/O. It then re-armed the next read while a write, a close or an injection ran on the strand, which the serial library's contract (shared objects are unsafe, use a strand) forbids. The completions now post onto the strand, and the first read is armed there too. ThreadSanitizer found it, and the unit tests that used the mock port from the test thread are fixed as well.
