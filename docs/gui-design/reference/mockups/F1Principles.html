1 Foundations

Principles and standards

Every screen on this canvas is checked against these. WCAG 2.2 AA is the benchmark, because WCAG 3.0 is still a working draft.

Nine design principles
1
Recognition over recall. Ports and links are picked from lists and cards. Addresses are previews, never required input.
2
Depth is revealed, never removed. Launcher, workspace, power tools. Advanced adds controls in the same window.
3
Plain language first. Two-way, split, join, monitor. Addresses and JSON sit one click away.
4
Say what will happen. Every dialog states the result in a sentence before the user commits.
5
Prevent, then explain. Self-links, loops and too few targets are blocked, and the refusal says what to do instead.
6
State is never colour alone. Text, a shape (filled or hollow) and colour say the same thing.
7
Fail visibly and locally. Errors name the operation, the cause and the next step. Work is never lost.
8
Keyboard first. Every action has a menu item. Ctrl+K finds anything, including hidden Advanced tools.
9
Follow the platform. System font, colour scheme, text size, native dialogs and shortcuts.

Human factorsHick: four launcher jobs, not twenty menu items. Fitts: large primary targets. Response limits of 0.1 s, 1 s and 10 s set the feedback rules. Jakob: platform conventions.

Three people, one window
OperatorBasic

"My program needs a serial port and this PC has none." Needs a port that exists and its name. Never needs the word topology.

IntegratorIntermediate

"Several programs must share one device." Repeats the same rig, moves between guided forms and addresses.

DiagnosticianAdvanced

"Why is nothing arriving, and which build is this?" Reads counters, lines and traffic. Wants raw addresses, faults and reproducible files.
